# GB Kids Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Alunos Adultos e Kids no GB Admin, com abas por categoria e graduação kids (faixas coloridas, regras próprias).

**Architecture:** Aluno ganha `categoria`; faixas kids em `js/ui/faixa.js`; regras kids em `js/logica/graduacao.js` (`aptidao` escolhe a tabela pela categoria); dados fictícios ganham 18 crianças, turmas kids e plano Kids; telas usam um componente de abas em `js/telas/comum.js` com a aba lembrada em memória.

**Tech Stack:** HTML/CSS/ES modules, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-20-gb-kids-design.md`

## Global Constraints
- Só front e dados fictícios; `VERSAO` dos dados sobe para 4.
- Ids de faixa kids: `branca, cinza-branca, cinza, cinza-preta, amarela-branca, amarela, amarela-preta, laranja-branca, laranja, laranja-preta, verde-branca, verde, verde-preta`.
- Regras kids padrão: `{ aulasPorGrau: 20, mesesPorGrau: 2, mesesMinFaixa: 6, idadeMin: { cinza: 4, amarela: 7, laranja: 10, verde: 13 }, idadeAdulto: 16 }`.
- Turmas kids: `programa: "Kids"`, campo `publico` ("4–6 anos", "7–10 anos", "11–15 anos", "Todas as idades").
- Produtos & estoque sai do menu e do registro de telas.
- Todo texto de dados passa por `esc()`.

## Review Focus
- Criança com 4 graus mas sem idade mínima da próxima cor → não aparece apta (teste Task 2).
- Kids com 16+ anos → aviso de passar para Adultos, nunca "apta" a faixa kids depois da verde-preta (teste Task 2).
- Aba Kids sem crianças (após filtros) → mensagem vazia, sem erro (navegador Task 4).
- Aluno kids sem responsável preenchido (cadastro) → validação pede nome e telefone do responsável (navegador Task 4).
- Comunicação para kids usa telefone e nome do responsável (teste Task 6).
